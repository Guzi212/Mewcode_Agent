# MewCode 跨平台执行与 Windows 原生支持 Spec

## 背景

MewCode 的对话界面、Provider、Agent Loop 和工具内部逻辑已经可以在 Windows 上启动并运行，但工具执行边界最初以 macOS 为主要开发环境：macOS 已接入 Seatbelt 沙箱，Windows 后端目前会明确返回不可用，命令执行、超时终止和部分测试也依赖 POSIX 行为。因此，Windows 用户虽然可以进入 TUI 并进行纯文本对话，却无法让 Agent 读取、修改、搜索项目文件或执行命令。

成熟的终端编程 Agent 通常不为每个操作系统维护相互分叉的产品版本，而是共享对话、工具、权限和界面核心，并在执行边界使用平台原生实现。本阶段将沿用这一模式：继续保持单一产品和单一代码库，在不削弱既有安全要求的前提下，为原生 Windows 补齐可执行的系统级隔离能力，并统一平台相关的 Shell、路径和进程生命周期行为。

本阶段聚焦 macOS 与原生 Windows：macOS 既有行为必须保持稳定，Windows 从“仅聊天可用”提升为“完整工具链可用”。Linux 与 WSL2 继续保持失败关闭，不在本阶段补齐其沙箱执行后端。

## 目标

- 保持单一 MewCode 产品、代码库和用户体验，不维护按操作系统长期分叉的功能版本。
- 使原生 Windows 用户能够在系统级隔离边界内使用全部内置文件、搜索和命令工具。
- 保持 macOS 现有 Seatbelt 工具执行、权限审批和失败关闭行为不回归。
- 让命令解释、标准输入输出、退出码、超时和进程树终止符合当前操作系统的原生语义。
- 让工作区、临时目录和经用户批准的外部路径在 macOS 与 Windows 上遵循一致的读写权限模型，且不能通过路径别名、链接或子进程绕过边界。
- 保持工具进程无法读取 Provider 密钥等敏感环境变量，并默认禁止工具网络访问。
- 建立可在 Windows 自动执行的单元、集成与端到端验证，避免平台专属测试在其他操作系统产生误报。

## 功能需求

- **F1（统一平台选择）**：应用启动时自动识别当前操作系统并选择对应的原生执行后端。对话、工具定义、权限审批和结果格式保持平台无关；用户无需安装或切换另一套 MewCode 产品版本。

- **F2（Windows 原生系统级隔离）**：原生 Windows 上的全部内置工具必须在低权限隔离进程中执行。默认只允许读取运行工具所需的系统与运行时文件，并允许当前工作区和系统临时目录按既有权限模型读写；工作区外路径没有明确授权时不可访问。隔离能力无法建立时返回结构化错误，绝不退化为普通用户权限直接执行。

- **F3（Windows 沙箱准备与能力检查）**：系统能够检查 Windows 版本、处理器架构和必需隔离组件是否可用，并在首次使用前创建或校验 AppContainer profile。标准准备在当前普通用户范围内完成；如果企业策略或系统配置导致某项修复需要管理员参与，该步骤必须与日常运行分离，说明将进行的系统变更并要求明确确认。日常启动和工具调用不得要求管理员身份。组件缺失、版本不支持或准备失败时，用户能看到具体原因和可操作的恢复提示。

- **F4（平台原生命令语义）**：命令工具在 macOS 使用 POSIX Shell 语义，在原生 Windows 使用 PowerShell 语义。系统向模型明确当前平台和 Shell，命令测试不得用另一平台的语法作为共同前提。命令的工作目录、字符编码、标准输出、标准错误和退出码在两端具有一致的结果契约。

- **F5（进程树生命周期）**：命令正常结束时返回完整退出状态；达到超时时间或用户取消时，系统终止该命令及其在本次工具调用中创建的全部后代进程，并在有限时间内回收输出与系统资源。终止失败不得留下应用无法退出或后续工具无法运行的状态。

- **F6（Windows 路径与真实目标校验）**：Windows 路径处理支持盘符、反斜杠、大小写不敏感和包含空格的路径。授权判断基于规范化后的真实目标；符号链接、目录联接及其他重解析点不能把工作区内授权扩大到工作区外。单文件授权、目录授权以及读、写、执行权限继续保持最小范围。

- **F7（网络与敏感环境隔离）**：工具进程及其子进程默认无法访问网络，也不能继承 Provider API 密钥、认证令牌、代理凭据或其他应用敏感环境变量。为运行时和 Shell 保留的环境必须使用明确的最小集合；隔离失败时拒绝执行。

- **F8（外部路径审批一致性）**：Windows 与 macOS 使用相同的拒绝、仅本次允许和本会话允许三种审批结果。审批界面显示工具、规范化目标、权限类型和命令摘要；授权仅作用于对应平台沙箱内的当前调用或当前会话，应用退出后失效。

- **F9（安装与发布完整性）**：Windows 支持所需的原生隔离组件必须与应用版本匹配，并能够通过项目规定的安装或构建流程获得。启动时发现组件缺失、架构错误、版本不匹配或签名/完整性校验失败时，系统拒绝使用该组件并给出明确诊断，不从未知路径加载同名可执行文件。

- **F10（平台状态与错误反馈）**：平台识别、沙箱准备、Shell 启动、路径授权、进程终止和组件校验中的失败均转换为可区分的结构化错误。TUI 显示对用户有用的摘要，详细信息足以定位问题但不得包含密钥、令牌或不必要的个人路径数据；一次工具失败不导致会话崩溃。

- **F11（macOS 行为保持）**：macOS 继续使用现有系统级沙箱执行全部工具，并保持工作区边界、临时目录、外部路径审批、网络禁用、敏感环境清洗、超时及结构化结果行为。Windows 适配不得要求 macOS 用户安装 Windows 组件或改变其启动方式。

- **F12（跨平台验证入口）**：测试和验收命令能够识别运行平台，只执行当前平台适用的原生沙箱场景，并明确跳过不适用场景。Windows 端到端验证至少覆盖启动 TUI、执行文件读取与写入、运行成功和失败命令、命令超时、工作区外拒绝以及正常退出。

## 非功能需求

- **N1（安全优先）**：系统以最小权限和失败关闭为默认原则。任何平台能力探测、组件准备、权限设置或进程创建异常都不得扩大文件、网络、身份或环境变量访问范围；不得以“兼容模式”为由静默关闭沙箱。

- **N2（支持基线）**：本阶段正式支持 macOS 13 及以上版本，以及 Windows 10 1809 及以上或 Windows 11 的 x86-64 环境。Windows ARM64、Windows on ARM 的 x64 仿真、Windows Server、网络共享工作区和非 NTFS 工作区不承诺完整支持，并在检测到时给出明确状态。

- **N3（响应性）**：沙箱准备、工具执行和进程回收均不得阻塞 TUI 事件循环。首次准备可以显示进度，后续单次工具调用不应重复执行系统级初始化；长耗时命令持续受现有超时和取消机制控制。

- **N4（可靠性与幂等性）**：Windows 沙箱准备可安全重复执行，中途失败或应用崩溃后再次运行能够恢复或给出清理指引。每次工具调用结束后回收进程、句柄、临时授权和临时文件；不得留下持续运行的后代进程或永久扩大的工作区权限。

- **N5（可维护性）**：平台差异限制在明确的执行、Shell、路径和沙箱适配边界内。Agent Loop、Provider、工具协议、权限模型和 TUI 不复制为 Windows 专用版本，也不散布无法测试的平台条件分支。

- **N6（可测试性）**：纯逻辑测试在所有开发平台运行；原生隔离和进程测试在对应平台运行。平台不适用的测试必须用显式条件和原因跳过，不能因当前路径不存在或权限不足而偶然失败。Windows 自动化测试不得要求交互式管理员会话；如需覆盖企业策略下的管理员修复流程，应使用隔离测试或可审计的替身验证。

- **N7（发布完整性）**：正式发布的 Windows 隔离组件与 MewCode 版本和目标架构一一对应，并具有可验证的来源与完整性信息。本地开发构建必须被明确识别为开发产物，只从项目规定位置加载；正式模式不得加载任意 PATH 或工作目录中的同名组件。

- **N8（兼容性）**：现有配置文件、Anthropic/OpenAI Provider、纯文本对话、Agent Loop、Plan Mode、工具名称和工具结果格式保持兼容。macOS 用户不需要迁移配置；Windows 用户除沙箱首次准备外不需要更改模型配置。

- **N9（敏感信息保护）**：错误、日志、测试输出和诊断状态不记录 API 密钥、认证令牌、代理凭据或完整环境变量。路径信息只在权限确认和必要诊断中展示，不上传到外部服务。

- **N10（可诊断性）**：用户可以区分“不支持的平台”“组件缺失”“组件版本不匹配”“首次准备未完成”“沙箱权限拒绝”“Shell 启动失败”“命令超时”和“进程回收失败”。诊断信息包含下一步操作，不以原始系统异常或乱码作为唯一反馈。

- **N11（开发体验）**：项目开发说明提供 macOS 和 Windows 各自的环境准备、依赖安装、原生组件构建、测试和端到端验收命令。命令示例使用当前平台的原生语法，并明确标准流程不要求管理员身份；若记录企业策略下的修复步骤，必须标明哪些操作需要管理员确认。

- **N12（改动约束）**：本阶段只处理原生 Windows 工具执行及其必要的跨平台抽象，不借机重构 Provider、Agent Loop、TUI 视觉、工具协议或配置体系。新增依赖仅限实现和验证系统级隔离所必需的最小集合。

## 不做的事

- 不在本阶段补齐 Linux 或 WSL1/WSL2 的 Bubblewrap 执行后端；这些平台继续在沙箱不可用时失败关闭。
- 不支持 Windows ARM64、Windows Server、网络共享路径、映射网络盘、非 NTFS 工作区或远程文件系统的完整沙箱语义。
- 不提供关闭沙箱、跳过权限检查或以普通用户完整权限直接执行工具的兼容模式。
- 不让 MewCode 日常运行在管理员身份下，也不让模型或工具自行触发提权提示；企业策略下确需管理员参与的修复只能由用户显式启动。
- 不把 macOS 与 Windows 拆成独立产品、独立功能分支或两套 Agent、Provider、工具和 TUI 实现。
- 不实现可配置 Shell 选择器；本阶段 macOS 使用 POSIX Shell，原生 Windows 使用 PowerShell，不承诺 CMD、Git Bash、Cygwin 或 MSYS2 的一致行为。
- 不新增交互式 PTY 命令、后台长期任务、作业恢复、实时 stdin 转发或跨会话命令进程管理。
- 不开放工具网络访问，也不在本阶段增加域名白名单、代理转发或按命令审批的网络策略。
- 不持久化用户的外部路径授权、系统命令授权或会话权限；已有的单次和会话授权生命周期保持不变。
- 不以 Windows Sandbox 虚拟机、Docker、Hyper-V 虚拟机或远程执行服务替代本机低权限进程隔离。
- 不建设完整的 MSI、Microsoft Store、WinGet 或自动更新发布渠道；只保证项目规定的开发构建与应用安装流程能够获得匹配的 Windows 隔离组件。
- 不在本阶段采购或搭建商业代码签名基础设施；正式发布要求保留可验证完整性和未来接入平台代码签名的边界。
- 不重做现有文件、搜索、Provider、Agent Loop、Plan Mode、对话历史和 TUI 视觉设计，除非是 Windows 适配不可缺少的最小修改。

## 验收标准

- **AC1（F1、N5）**：在受支持的 macOS 与 Windows 环境使用同一份 MewCode 配置启动应用，均进入相同 TUI、加载相同工具集和权限选项，并自动报告当前平台对应的执行后端；不需要切换产品版本或平台专用配置文件。

- **AC2（F2、N1）**：在普通 Windows 用户会话中，沙箱准备完成后执行读文件、写文件、搜索和命令工具，工作区内操作成功；尝试直接访问未授权的工作区外文件或创建工作区外文件均失败且目标保持不变。隔离组件不可用时，同一调用返回 `sandbox_unavailable` 类结构化错误，宿主权限下没有发生实际工具操作。

- **AC3（F3、N2、N4）**：在未准备的受支持 Windows x86-64 普通用户环境首次使用工具时，应用显示准备状态和明确操作；用户显式运行准备命令后，系统创建或校验稳定的 AppContainer profile，无需以管理员身份日常运行。重复执行准备不会创建重复 profile、累积永久 ACL 或扩大 capability；模拟组件缺失、版本过旧、不支持架构和企业策略阻止 profile 创建时，分别显示可区分的恢复提示。

- **AC4（F4、N10）**：在 Windows 运行一组使用 PowerShell 变量、命令连接和错误流的命令，结果正确区分 stdout、stderr 与退出码，中文和 UTF-8 文本不乱码；同等 macOS 测试使用 POSIX 语法通过。Windows 测试不再依赖分号作为 POSIX 命令分隔符，macOS 测试不依赖 PowerShell 语法。

- **AC5（F5、N3、N4）**：命令工具启动一个持续运行并创建后代进程的测试任务，触发超时或取消后，父进程与全部后代进程在限定时间内退出，输出返回结构化超时或取消结果；随后立即执行另一条命令成功，应用可正常退出，系统中不存在该测试任务的残留进程。

- **AC6（F6）**：Windows 上分别使用包含空格的路径、不同大小写的同一路径、盘符路径和工作区内指向外部目录的链接或目录联接执行文件工具。合法工作区目标正常处理；所有解析到外部真实目标的未授权操作均被拒绝。仅授权一个文件时，同目录其他文件仍不可访问；只读授权不能用于写入。

- **AC7（F7、N9）**：工具进程检查其环境时看不到配置中的 API 密钥、认证令牌和测试代理凭据；工具命令尝试连接本地测试监听端口和外部网络均失败，而 Provider 的模拟网络请求仍可在主应用中完成。测试日志和错误输出不包含注入的敏感测试值。

- **AC8（F8）**：在 Windows 与 macOS 分别触发一次工作区外路径访问，审批界面均显示规范化路径、工具、权限和命令摘要。选择拒绝后目标未被访问；选择仅本次只读后当前调用可读但后续调用和写入失败；选择本会话目录写入后该目录内后续操作成功；重新启动应用后授权失效。

- **AC9（F9、N7）**：按项目文档在 Windows 完成开发安装或构建后，应用能定位唯一匹配的隔离组件并执行 smoke test。替换为错误架构、不同版本、内容被篡改或从非规定路径提供的同名组件时，应用拒绝加载并显示对应诊断；恢复正确组件后无需修改模型配置即可运行。

- **AC10（F10、N10）**：自动化测试分别触发不支持平台、准备未完成、权限拒绝、Shell 启动失败、命令非零退出、命令超时、组件不匹配和进程回收失败，均得到稳定且可区分的错误代码与中文摘要；TUI 不显示未捕获堆栈、不会崩溃，失败后下一轮纯文本对话仍可进行。

- **AC11（F11、N8）**：在 macOS 运行既有纯文本对话、Provider、Agent Loop、Plan Mode、文件工具、命令工具、Seatbelt 沙箱和路径审批测试，全部保持通过；使用已有配置启动真实 TUI，无需新增 Windows 字段或组件。

- **AC12（F12、N6）**：在 Windows 运行完整自动化测试，平台无关测试和 Windows 原生测试全部通过，macOS 专属测试以明确原因跳过且没有偶然失败；在 macOS 执行时结果对称。测试报告清楚区分通过、跳过和失败，不通过隐藏失败来获得绿色结果。

- **AC13（F12、N3）**：Windows 端到端会话中，用户启动 TUI 后依次让 Agent 读取文件、写入临时项目文件、搜索内容、执行成功命令、执行非零退出命令并触发超时；工具行、结果摘要和最终回答均符合实际结果，临时文件只出现在授权工作区内，最后通过 `/exit` 或 Ctrl+C 正常退出。

- **AC14（N4、N7）**：连续执行多轮文件与命令工具后，对比运行前后的工作区外 ACL、沙箱身份、规则和进程状态，没有会话授权或临时身份产生的永久权限扩大，也没有残留进程、句柄占用或无法清理的测试文件；开发组件和正式组件的加载路径可被诊断输出明确区分。

- **AC15（N11、N12）**：开发文档分别给出 macOS 和 Windows 的环境准备、依赖安装、隔离组件构建、测试与端到端验收步骤；由一名未参与实现的开发者按 Windows 文档从干净检出完成构建和 smoke test，不需要猜测额外命令或以管理员身份日常运行。
