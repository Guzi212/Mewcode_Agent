# MewCode Agent Loop Spec

## 背景

当前 MewCode 已具备流式对话、工具调用和一次“工具执行后续答”的单轮闭环：首次请求取得一批工具调用，执行并回灌结果后，第二次请求生成最终答复即停止；续答中再次出现的工具调用会被丢弃。遇到需要多步推理、检查结果后继续操作的任务时，模型无法自行推进，用户必须反复催促。

本章将 MewCode 升级为可自主推进任务的 Agent：模型持续接收工具结果、决定下一步并调整方案，直至完成任务或触发明确的停止条件。界面不再直接编排模型和工具，而是消费统一的异步事件流。

## 目标

- 支持 ReAct 式多轮 Agent Loop：模型响应、工具执行、结果回灌循环进行，直至模型给出最终答复。
- 为正常完成、迭代上限、用户取消、连续未知工具调用和流式错误提供明确、可观测的停止行为。
- 提供与界面解耦的异步事件流，覆盖文本、工具调用、工具结果、Token 用量与任务进度。
- 支持安全的多工具调度：只读调用可并发，可能产生副作用的调用按顺序执行。
- 提供 `/plan` 与 `/do` 两段式工作方式：前者仅允许读类工具制定计划，后者使用完整工具集执行。
- `Esc` 取消当前任务且保留已产生的对话历史，`Ctrl+C` 保持退出程序。

## 功能需求

- **F1（自主循环）**：以多轮 ReAct 循环替换现有单轮闭环。收到用户任务后，系统重复执行“带工具定义请求模型 → 流式收集响应 → 执行模型请求的工具 → 回灌工具结果”的循环；模型在某轮仅产生最终文本、不再请求工具时，任务正常结束。续答中的工具调用与首轮调用同等处理，不得丢弃。

- **F2（停止条件）**：系统必须在以下任一情况终止当前任务，并产生明确的结束原因：
  - 模型完成答复且未请求工具；
  - 达到配置的迭代上限；
  - 用户按 `Esc` 取消；
  - 连续 3 次请求未知工具；
  - 模型流式响应发生错误。
  迭代上限仅作为安全兜底，不替代其他停止条件。

- **F3（异步事件流）**：Agent 运行过程以统一、按时间顺序的异步事件流对外发布。事件至少包含文本增量、工具调用开始、工具结果结束（结果摘要及成功/错误状态）、Token 用量、迭代进度、本轮结束、任务结束与错误。界面只订阅和呈现事件，不直接驱动模型调用或工具执行。

- **F4（双路流式收集）**：每轮模型响应的文本增量须同时实时发布给界面，并累积为完整响应；循环根据完整响应及其中的工具调用判断下一步。名称与 JSON 参数分片到达的工具调用须正确拼接、解析为完整调用。流式过程中产生的工具调用、Token 用量和错误同样进入事件流。

- **F5（工具批次调度）**：单轮返回多个工具调用时，系统按模型返回顺序扫描：连续的只读调用组成一个并发批；具有写入、命令执行或其他副作用的调用各自串行执行。批与批之间保持原始相对顺序；并发批完成后，结果也按原始调用顺序回灌。每项调用无论成功或失败均发布结果；单项失败不阻断同批其他调用，且每项仍受现有的独立超时约束。

- **F6（结果回灌与历史一致性）**：每轮模型工具调用及其工具结果必须按序写入对话历史，下一轮请求携带完整历史。任何提前终止后，对话历史仍须保持协议合法、工具调用与结果完整配对，会话可继续；取消时，为已发起但未完成的工具调用补充“已取消”的结构化结果。

- **F7（取消后恢复）**：用户取消时，系统停止后续模型请求和未开始的工具调用，已开始的可取消工作尽快终止；界面收到取消结束事件后恢复可输入状态，已产生的对话、工具结果和进度保留。

- **F8（Token 用量统计）**：系统从每轮模型流中提取可用的输入与输出 Token 用量，跨轮累计为当前会话总量，并在状态栏展示。协议未提供用量时须明确标记为不可用。

- **F9（迭代进度展示）**：任务运行时，界面动态展示当前 Agent 迭代轮次，使用户能够观察多轮任务的推进。

- **F10（Plan Mode）**：用户输入 `/plan <任务>` 时，系统只向模型开放读类工具，并采用计划态提示引导模型检查现状、输出可执行计划；计划模式不得执行写入、命令或其他副作用工具。计划状态在本次任务的多轮请求中保持。`/plan <任务>` 生成并保留当前会话计划；`/do` 使用完整工具集及内置执行提示立即执行该计划，`/do <任务>` 使用完整工具集执行新指定任务。

## 非功能需求

- **N1（响应性与超时）**：模型流式输出、工具执行、并发调度和取消等待期间，TUI 必须保持可响应、可滚动；取消操作应立即反馈为“正在取消”，无需等待下一轮模型响应才生效。每项工具继续使用现有的内置超时，超时以结构化结果回灌而不终止循环。

- **N2（执行安全）**：沿用现有沙箱和外部路径授权边界。并发仅适用于互不产生副作用的调用；任何写文件、改文件、命令执行或其他可能改变外部状态的调用均不得与同批副作用调用并发。

- **N3（健壮性）**：未知工具、参数错误、工具异常、非零退出、超时、取消和流式错误均不得使程序崩溃。每种终止原因要以结构化事件和用户可读的提示呈现，之后可继续发起新任务。

- **N4（上下文与资源控制）**：每轮工具结果继续受现有体量限制；循环结束后不得再产生模型请求或未开始工具调用。默认迭代上限为 20，可由配置调整，配置无效时回退到安全默认值。

- **N5（协议一致性）**：Anthropic 与 OpenAI/兼容端点都应支持同一上层循环、停止条件、事件语义、Plan Mode 与工具调度规则；Token 用量在协议提供时发布，协议未提供时明确标记为不可用而非伪造数值。

- **N6（可测试性）**：循环、各停止条件、并发/串行调度、事件顺序、双路收集、Plan Mode 限制和取消行为均应由自动化测试覆盖；完成后在 tmux 中以真实对话完成至少一个多步工具任务及一次 `/plan` → `/do` 场景验收。

- **N7（兼容性）**：普通对话、现有单批工具调用路径、沙箱授权行为、纯文本流式输出及 `Ctrl+C` 退出语义不得回归。

- **N8（呈现顺序）**：跨多轮的前置文本、工具调用、结果摘要与最终答复须按实际发生顺序保留在对话历史中；并发批的工具行及结果按模型调用顺序排列，不得交错。

- **N9（并发与取消资源安全）**：并发批的执行和结果收集不得产生共享状态竞争；任务结束或取消后不得残留挂起的异步任务、队列或未关闭资源。

- **N10（代码质量）**：新增或修改的 Python 代码须符合项目既有格式与静态检查约定；项目配置相应工具后，格式化和 lint 检查应无告警。

## 不做的事

- 权限系统的重新设计、细粒度用户确认、权限持久化或授权策略扩展；继续沿用现有沙箱与外部路径授权机制。
- 上下文压缩、历史摘要、跨会话记忆或计划的跨会话持久化。
- 在任务中途向用户追问、等待确认后继续执行的交互式 Agent 工作流。
- 后台长期任务、任务队列、断线恢复、定时运行或并行执行多个独立 Agent 任务。
- 工具依赖图推断、自动重排有副作用调用，或以猜测结果为依据并发执行存在依赖的调用。
- 新增第三方工具、MCP 集成、工具市场或自定义工具加载。
- 改造现有沙箱实现、扩展其权限模型，或增加针对高风险操作的二次确认。
- 令 `/plan` 自动执行计划；计划只在用户显式输入 `/do` 后进入执行。
- 在模型无法提供 Token 用量时估算或伪造用量数据。
- 子 Agent、任务分解工具或独立任务队列。
- 基于 Token 预算自动停止任务；本章只统计和展示用量。
- 多模态对话或非文本工具结果，以及工具结果的流式产出。

## 验收标准

- **AC1（F1）**：使用需要至少两轮工具调用的真实任务时，系统在无需用户催促的情况下完成多次“模型 → 工具 → 结果回灌”循环，并在模型不再请求工具后输出最终答复。

- **AC2（F1、F2）**：模型某轮只输出最终文本、不请求工具时，任务以“已完成”结束；该文本完整显示并写入会话历史，之后可继续输入下一条消息。

- **AC3（F2、N4）**：将上限设为较小值并触发超限后，系统不再调用模型或执行未开始的工具，发布并显示“已达到迭代上限”的结束原因；默认值为 20，配置可覆盖它。

- **AC4（F2、F7、N1）**：运行含等待或多步工具的任务时按 `Esc`，系统显示取消进度并停止后续工作；已产生的文本、工具结果和进度保留，输入恢复可用，`Ctrl+C` 仍退出程序。

- **AC5（F2、N3）**：连续三轮请求未知工具时，系统以对应原因结束且不崩溃；任意轮模型流式错误时，系统发布错误和结束状态、不再继续循环，之后仍可发起新任务。

- **AC6（F3）**：一次任务可按时间顺序观察到文本、工具调用开始、工具结果结束、Token 用量、迭代进度、本轮结束、任务结束和错误事件；界面仅依赖这些事件呈现任务过程。

- **AC7（F4）**：文本在到达时实时显示；同一轮中分片到达的工具名称和 JSON 参数被正确拼接为完整调用，并用于下一轮判断。

- **AC8（F5、N2、N8）**：一次回复含多个工具调用时，连续只读调用并发执行，含写入或命令的调用串行执行，批与批保持模型给出的相对顺序；结果按原始顺序回灌和呈现。单个调用失败不阻断同批其他调用，且每项均有结果事件。

- **AC9（F6、F7、N9）**：多轮模型工具调用与工具结果按序入历史；取消、上限或出错终止后工具调用与结果仍完整配对，不产生协议错误，且可继续对话。取消后没有遗留的异步工作。

- **AC10（F8）**：状态栏展示会话累计输入与输出 Token 用量，并随轮次更新；不提供用量的协议明确显示不可用。

- **AC11（F9）**：任务运行期间，动态区域显示当前迭代轮次。

- **AC12（F10）**：`/plan <任务>` 后模型仅使用读类工具产出计划，不执行写入或命令；`/do` 立即按当前会话计划进入全工具执行，`/do <任务>` 则执行新指定任务。

- **AC13（N5、N7）**：在 Anthropic 和 OpenAI/兼容端点配置下，循环、停止条件、事件呈现、Plan Mode、Token 用量和取消行为一致；普通纯文本对话和已有工具场景仍正常工作。

- **AC14（N1、N6、N10）**：自动化测试覆盖上述关键行为；项目已有或新增的格式化和 lint 检查通过；在 tmux 启动 MewCode，完成一次真实多步任务和一次 `/plan` → `/do` 流程，并按 checklist 记录可观测结果。
