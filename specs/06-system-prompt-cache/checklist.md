## 模块化系统提示

- [x] **固定模块顺序（AC1）**：稳定提示严格按“身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出”排列。（验证：构建默认提示，定位各模块的唯一标志文本并比较索引。）
- [x] **分隔与空白（AC1）**：非空模块之间恰有一个空行，结果无首尾空白或连续三个换行。（验证：模块装配单元测试。）
- [x] **同优先级稳定顺序（AC1、N1）**：多个同优先级测试模块按声明顺序输出，两次构建逐字节相同。（验证：重复构建并比较 UTF-8 字节。）
- [x] **可选空槽（AC2）**：自定义指令、已激活 Skill、长期记忆为空时不出现在结果中且不留下空行。（验证：默认模块装配测试。）
- [x] **局部扩展（AC2、N8）**：只声明一个新模块即可按优先级插入，无需修改装配器分支。（验证：向输入序列加入测试模块并观察输出位置。）

## 动态环境与确定性

- [x] **环境字段完整（AC3）**：动态块可观察到工作目录、平台、架构、Shell、日期、Git 摘要、应用版本、Provider 和模型。（验证：使用固定 `cwd`、日期和 Provider 构造环境 reminder。）
- [x] **稳定与动态分块（AC3、AC4）**：环境信息是稳定 System 之后的独立系统补充项，不出现在 `SYSTEM_PROMPT` 正文中。（验证：捕获 Conversation 请求项。）
- [x] **动态变化不破坏稳定前缀（AC4）**：改变日期、目录、Git 状态、Plan 轮次和历史后，稳定 System 与相同工具定义逐字节不变。（验证：参数化请求捕获测试。）
- [x] **稳定输入变化可区分（AC4）**：改变模块内容、可选模块内容、工具定义或工具顺序会改变对应稳定前缀。（验证：参数化构造测试。）
- [x] **非 Git 降级（AC14）**：非 Git 目录正常生成环境块并发起请求，不出现未处理异常。（验证：临时非 Git 目录单元测试。）
- [x] **Git 不可用与超时降级（AC14、N4）**：Git 缺失、失败或超时时显示安全状态且事件循环可继续响应。（验证：替身异常、超时和异步心跳测试。）
- [x] **环境隐私（AC3、AC14、N5）**：环境块不包含哨兵 API Key、敏感环境变量、remote URL、文件名、文件内容或配置原文。（验证：设置哨兵值并遍历输出。）

## 缓存协议与用量

- [x] **Anthropic 稳定系统缓存（AC5）**：稳定 system 文本块带 `cache_control: ephemeral`。（验证：捕获 Anthropic 请求 JSON。）
- [x] **Anthropic 稳定工具缓存（AC5）**：最后一个稳定工具定义带缓存控制，工具顺序和 schema 不变。（验证：捕获 Anthropic 请求 JSON。）
- [x] **Anthropic 动态块不标记（AC5）**：环境与 Plan reminder 位于稳定 system 块之后且不带缓存控制。（验证：使用两组动态上下文比较捕获请求。）
- [x] **OpenAI 稳定前缀（AC6）**：稳定 System 始终为第一条消息，相同稳定内容和工具顺序产生相同请求前缀。（验证：捕获两轮 OpenAI-compatible 请求。）
- [x] **OpenAI 不发送缓存扩展（AC6）**：请求中没有 MewCode 添加的 `cache_control`、TTL、断点或预热参数。（验证：递归检查捕获的请求 JSON。）
- [x] **Anthropic 用量解析（AC7）**：创建、读取、未缓存输入和输出被解析，总输入等于三类输入之和。（验证：模拟流式 usage 快照。）
- [x] **OpenAI 用量解析（AC6、AC7）**：标准 cached token、可选写入字段与 DeepSeek 命中兼容字段正确映射，标准字段优先。（验证：参数化模拟响应。）
- [x] **未知与零区分（AC7、N6）**：字段缺失、布尔、负数或字符串时为 `None`；端点明确返回 0 时为 0，且当前请求不中断。（验证：两个 Provider 的非法字段参数化测试。）
- [x] **最终快照单次累计（AC8）**：一轮多个用量快照只累计最后值，多轮分别累计一次。（验证：ScriptedProvider 发布多个快照并检查最终 usage。）
- [x] **TUI 不展示缓存明细（AC8、范围）**：状态栏仍只显示输入和输出总量，不出现 cache/read/write 字样。（验证：Textual pilot 或状态格式单元测试。）
- [x] **Smoke 未知状态（AC8）**：端点不返回缓存字段时脚本打印 `unknown`，而非 0 或异常。（验证：替身输出捕获。）

## 工具规则双重强化

- [x] **专用工具优先（AC9）**：固定工具模块和 `find_files`、`search_code`、`run_command` 描述都能定位到专用查找/搜索优先规则。（验证：提示与工具定义文本断言。）
- [x] **编辑前读取（AC9）**：固定工具模块和 `read_file`、`edit_file`、`write_file` 描述都能定位到编辑前读取规则。（验证：提示与工具定义文本断言。）
- [x] **精确修改（AC9）**：固定工具模块和编辑工具描述都说明局部修改优先精确编辑，匹配失败不得用整文件覆盖掩盖。（验证：提示与工具定义文本断言。）
- [x] **依据工具结果陈述（AC9）**：固定工具模块和执行相关工具描述都要求只依据实际返回声称成功或通过。（验证：提示与工具定义文本断言。）
- [x] **工具契约不变（N2）**：名称、参数 schema、只读标记和默认顺序没有因描述更新而改变。（验证：既有工具注册表测试。）

## 系统补充项与 Plan Mode

- [x] **系统级 reminder（AC10）**：补充项带完整 `<system-reminder>` 标签，Anthropic 序列化为 system 内容块，OpenAI-compatible 序列化为 system 消息。（验证：捕获两个 Provider 请求。）

- [x] **双层只读限制（AC11、N9）**：Plan Mode 只向模型暴露只读工具，执行层直接收到副作用调用时仍拒绝。（验证：工具定义捕获 + 执行器回归测试。）
- [x] **`/do` 恢复执行（AC11）**：退出 Plan Mode 后完整工具集恢复，并可按已确认计划执行。（验证：tmux 真实对话。）
