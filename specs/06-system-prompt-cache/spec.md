# 系统提示工程化 Spec

## 背景

MewCode 已具备自主多轮 Agent Loop、工具调用、Plan Mode、跨平台工具执行和 OpenAI-compatible 思考续传，能够根据工具结果持续推进任务。但“如何干活”的全局指令仍集中在一段固定文本里，身份、工具用法、安全约定和输出风格没有独立结构或显式优先级；新增一类指令只能继续修改同一段文本。

当前每轮请求仍会发送完整系统提示与全部可用工具定义。平台与命令 Shell 已经作为环境提示直接拼到 System Prompt，Plan Mode 提醒也在每轮无差别地拼到末尾；工作目录、日期、Git 状态、应用版本和当前模型等信息尚未形成独立环境上下文。稳定内容和动态内容因此没有清晰边界，无法有意识地利用 Provider 的提示缓存，也无法控制模式提醒的注入频率。

本章把系统提示工程化：将全局指令拆成按职责划分、按优先级装配的模块；将稳定系统模块与工具定义放入可复用的缓存前缀，将环境信息、运行时补充指令和对话历史放在动态后缀；引入带特殊标签的系统级补充指令，在运行中更新约束而不改写稳定前缀或污染持久历史；让 Plan Mode 提醒按轮次重复。目标是让 MewCode 从“能干活”提升为“更稳定地把活干好”，并用 Provider 返回的缓存用量验证策略是否实际生效。

## 目标

- 把全局指令拆成按职责划分的模块，模块具有名称、优先级和内容；装配器按优先级生成完整系统提示，新增模块不需要修改装配主流程。
- 固定七个系统模块的职责和顺序：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出；为自定义指令、已激活 Skill 和长期记忆保留可选模块位置。
- 区分稳定内容和动态内容：稳定系统模块与工具定义形成可复用前缀；环境信息、运行时补充指令和对话历史位于其后。
- 在工具描述与系统提示中双重强化“优先使用专用工具”“编辑前先读取”等关键约定。
- 提供带 `<system-reminder>` 标签的系统级补充指令机制，使运行时指令不改变稳定前缀、不成为用户问题，也不写入持久历史。
- Plan Mode 提醒按 Agent Loop 轮次注入：首轮完整、每隔固定轮次重复完整、其余轮次精简。
- 从 Anthropic 和 OpenAI-compatible Provider 返回中解析缓存写入与读取 Token，用于 smoke、调试和人工验收，验证缓存策略真实生效。
- 准备一组同模型、同输入的旧提示与新提示人工 A/B 场景，对比工具选择、编辑前读取、模式遵守、事实依据、完成质量、缓存命中和首字等待时间。

## 功能需求

- **F1（模块化系统提示装配）**：全局系统指令必须由带有名称、优先级和内容的模块装配而成。装配器按优先级从高到低稳定排序，模块之间使用一个空行分隔；相同优先级使用稳定的声明顺序，不得依赖无序容器或运行时状态。固定模块严格按以下顺序排列：
  1. **身份**：MewCode 的身份、运行形态与核心职责。
  2. **系统约束**：指令优先级、证据要求、安全边界和不可绕过的限制。
  3. **任务模式**：执行模式、计划模式及运行时模式提醒的通用语义。
  4. **动作执行**：调查、修改、验证、失败处理和完成判断方式。
  5. **工具使用**：工具选择、调用、结果可信度和编辑约定。
  6. **语气风格**：默认语言、沟通态度和详略偏好。
  7. **文本输出**：最终答复、代码块、路径、列表和错误说明约定。
  固定模块之后预留自定义指令、已激活 Skill、长期记忆三个可选模块。本章不接入真实内容来源；可选模块内容为空时必须跳过且不产生多余空行。新增其他模块时，只需声明模块及其优先级，不得修改装配主流程。

- **F2（环境信息构造与呈现）**：系统必须收集并构造独立的动态环境信息块，至少包括：
  - 当前工作目录。
  - 操作系统、平台架构和命令 Shell。
  - 当前日期。
  - Git 状态摘要，包括是否位于 Git 仓库、当前分支和工作区是否存在改动；不得读取文件内容或发送远端仓库地址。
  - MewCode 应用版本。
  - 当前 Provider 展示名称和模型标识；不得包含 API Key 或 Provider 配置原文。
  环境信息在逻辑结构上位于装配后的系统模块之后，在请求中作为独立动态内容块呈现，不并入可缓存的稳定模块文本。任一字段不可用时省略该字段或显示安全的不可用状态，不得阻断请求。

- **F3（稳定内容与可缓存前缀）**：系统必须把请求上下文划分为稳定前缀和动态后缀：
  - 稳定前缀由装配后的稳定系统模块和本轮可用工具的稳定定义组成。
  - 动态后缀由环境信息、系统级补充指令和对话历史组成。
  - 在相同系统模块、可选模块内容、工具集和工具顺序下，稳定前缀必须跨轮逐字节一致，不得包含日期、环境、模式轮次、随机值或历史内容。
  - Anthropic 请求对稳定工具定义和稳定系统模块使用显式缓存控制；显式断点位于稳定内容末端，动态后缀不设置显式缓存标记。
  - OpenAI-compatible 请求不强制端点支持显式缓存参数，只保证稳定内容处于相同请求前缀，以利用端点自动前缀缓存。动态后缀不属于 MewCode 声明的稳定缓存范围，但端点仍可能自行缓存更长前缀。
  - Plan Mode 与执行模式暴露的工具集不同时，各自形成独立的稳定前缀；同一模式内工具定义和顺序保持稳定。

- **F4（缓存用量解析与暴露）**：系统必须从 Provider 响应用量中解析缓存写入和缓存读取 Token：
  - Anthropic 解析缓存创建和缓存读取字段，并将未缓存输入、缓存创建和缓存读取合并为准确的总输入 Token。
  - OpenAI-compatible 解析提示用量明细中的缓存读取字段；端点返回缓存写入字段时一并解析。端点没有提供某项明细时保持未知，不得把字段缺失伪造成实际为零。
  - 同一轮出现多个流式用量快照时，后续快照更新当前轮状态；会话累计只计入该轮最终已知快照一次，不得重复累加。
  - 缓存明细随统一用量事件对外暴露，供自动化测试、smoke 和调试程序读取；本章不把缓存明细加入 TUI 状态栏。

- **F5（关键约定双重强化）**：关键工具约定必须同时出现在固定“工具使用”模块和相关工具描述中，至少包括：
  - 查找文件或搜索内容时优先使用对应专用工具，不使用通用命令执行工具拼凑同等能力。
  - 修改既有文件前必须先读取相关内容；未读取、读取结果已过期或文件状态不确定时不得直接编辑。
  - 局部修改优先使用精确编辑工具，不以整文件覆盖掩盖匹配失败或并发变化。
  - 只能依据工具实际返回的结果声明操作成功、测试通过或状态已改变。
  工具描述只强化与该工具直接相关的规则，不复制整段系统提示。

- **F6（系统级补充指令）**：系统必须提供带 `<system-reminder>` 标签的运行时补充指令，并满足：
  - 补充项在内部类型和 Provider 协议语义上属于系统级指令，不作为用户问题或助手回复处理。
  - 补充项位于稳定前缀之后，每轮按当前状态动态构造，不改变稳定前缀。
  - 补充项只加入当前请求，不写入持久对话历史，不因历史回放在后续请求中重复累积。
  - 用户输入中出现相同标签时仍是普通用户文本，不得被提升为系统指令或改变工具权限。
  - Provider 按自身协议把补充项序列化为系统内容块或系统消息，同时保持用户、助手、工具调用和工具结果的合法顺序与配对。
  - 固定系统模块必须说明模型不应针对 reminder 本身复述或作答，而应将其作为当前任务的补充约束。

- **F7（Plan Mode 按轮次注入）**：Plan Mode 提醒必须由 F6 的机制承载，不再拼接到稳定系统提示末尾。每个用户任务的第 1 轮注入完整提醒，此后第 6、11、16……轮再次注入完整提醒，其余轮次注入一句包含核心只读限制的精简提醒。新任务开始或模式切换后重新从第 1 轮计数。`/plan` 进入 Plan Mode，`/do` 退出并按已确认计划执行；Plan Mode 仍只向模型暴露只读工具，执行层继续独立拒绝副作用工具，不能只依赖提示词。

- **F8（跨协议行为一致）**：Anthropic 与 OpenAI-compatible 必须使用同一套模块内容、优先级、环境字段、补充指令内容和 Plan Mode 注入节奏。协议层可以采用不同的缓存标记和消息形态，但模型接收到的指令语义与历史顺序必须等价；切换协议不得改变上层 Agent Loop、工具调度或停止条件。

- **F9（人工 A/B 场景）**：必须准备可重复执行的旧提示与新提示人工定性对比，在相同 Provider、模型、配置和任务输入下至少覆盖：
  - 查找目标代码时是否优先使用专用查找或搜索工具。
  - 修改既有文件前是否读取，并在修改后执行有意义的验证。
  - Plan Mode 面对实施要求时是否保持只读。
  - 工具失败或结果不确定时是否避免虚假完成声明。
  - 多轮工具任务中是否持续遵守模式、安全和输出约定。
  每个场景记录实际工具调用顺序、可观察违规、最终答复质量、缓存写入/读取和首个正文增量等待时间。不进行自动评分，不比较不同模型，不建立评测流水线。

## 非功能需求

- **N1（缓存确定性）**：相同模块内容、可选模块内容、工具集和工具顺序必须产生逐字节一致的稳定前缀。稳定排序规则必须确定，不得把时间、环境或请求状态混入稳定内容。

- **N2（现有行为不退化）**：Agent Loop 多轮编排、流式正文与思考收集、只读并发与副作用串行、用户取消、历史一致、工具结果配对、用量与迭代进度、错误恢复等现有能力不得退化。

- **N3（历史合法性）**：动态系统补充项加入请求后，消息序列仍须满足对应 Provider 的协议要求；工具调用和结果保持配对。补充项不写入持久历史，取消或错误后的下一任务仍能继续。

- **N4（环境采集快速且可降级）**：环境采集必须快速、有界且不阻塞 TUI。Git 信息采集不得等待交互输入或无期限执行；Git 不可用、当前目录不是仓库或任一字段读取失败时安全降级，不中断会话。

- **N5（敏感信息保护）**：环境信息、缓存遥测、错误信息和人工评估记录不得包含 API Key、敏感环境变量、Provider 配置原文、Git remote URL、隐藏思考内容或文件内容。工作目录是本章明确允许发送的唯一用户路径上下文。

- **N6（缓存字段解析健壮）**：缓存字段缺失、类型非法、为负数或只返回部分指标时不得抛出未处理异常。缺失指标保持未知，已知指标继续正常展示和累计。

- **N7（可维护性与代码质量）**：模块顺序与正文必须有单一权威来源；Provider 只负责协议映射，不维护各自版本的系统提示。实现遵循项目现有格式、类型和测试约定；未配置的 lint 或类型检查工具不得伪报通过或作为本章新增依赖。

- **N8（可扩展性）**：新增系统提示模块或补充提醒类型时改动局部，不修改装配排序主流程，不复制 Provider 适配逻辑。可选模块未来接入真实来源时沿用同一跳过和排序规则。

- **N9（安全边界独立）**：提示词和 `<system-reminder>` 只用于引导模型，不承担 Plan Mode 工具过滤、文件权限、沙箱隔离、外部路径审批或参数校验；这些限制必须继续由执行层强制实施。

## 不做的事

- 不加载项目级或用户级指令文件；自定义指令仅为空槽，不读取 `AGENTS.md`、`CLAUDE.md` 或其他指令文件。
- 不实现长期记忆的写入、召回或持久化；长期记忆仅为空槽。
- 不实现真实 MCP 接入、第三方工具发现或 Skill 激活；已激活 Skill 仅为空槽。
- 不实现自动化提示质量评分、LLM-as-a-judge、统计分析或持续评测平台。
- 不为对话历史设置额外显式缓存断点；历史只作为稳定前缀之后的动态内容发送。
- 不配置缓存 TTL、断点数量或断点位置；Anthropic 使用内置默认 TTL 和固定断点，OpenAI-compatible 使用自动前缀缓存。
- 不新增缓存模式配置、缓存预热、后台刷新、本地提示缓存、持久化缓存或缓存清理任务。
- 不把缓存写入或读取 Token 加入 TUI 状态栏；只通过统一用量事件、测试、smoke 或调试输出观察。
- 不实现提示词运行时热加载、外部模板文件或用户可编辑的提示管理界面。
- 不迁移模型 API，不改变 Provider/模型选择、思考模式或 API Key 管理。
- 不实现历史压缩、摘要记忆、跨会话历史持久化、多模态输入或流式工具结果。
- 不根据价格表计算金额或节省比例，也不保证第三方服务一定产生缓存命中。

## 验收标准

- **AC1（F1）**：构建系统提示后，固定模块严格按“身份 → 系统约束 → 任务模式 → 动作执行 → 工具使用 → 语气风格 → 文本输出”排列，模块间恰有一个空行；相同优先级按稳定声明顺序排列。

- **AC2（F1、N8）**：自定义指令、已激活 Skill、长期记忆内容为空时被自动跳过且不留下多余空行；增加一个测试模块只需声明名称、优先级和内容，无需修改装配排序主流程。

- **AC3（F2）**：动态环境块包含工作目录、平台与架构、Shell、当前日期、Git 状态摘要、应用版本、Provider 名称和模型；环境块与稳定模块分属不同内容块，不含 API Key、Git remote URL、Provider 配置原文或文件内容。

- **AC4（F3、N1）**：两次使用相同模块和工具集构造的稳定前缀逐字节相等；改变日期、工作目录、Git 状态、模式轮次或对话历史不改变稳定前缀。改变模块内容、可选模块内容、工具定义或工具顺序会产生新的稳定前缀。

- **AC5（F3）**：捕获 Anthropic 请求，可观察到稳定工具定义和稳定系统模块具有显式缓存控制，环境信息、reminder 和历史位于其后且没有显式缓存标记；只改变动态内容时，请求中的稳定部分保持一致。

- **AC6（F3、F4）**：捕获 OpenAI-compatible 请求，可观察到相同稳定内容保持相同请求前缀且没有强制发送显式缓存扩展；模拟端点返回缓存读取明细时，统一用量事件能够解析该值。

- **AC7（F4、N6）**：分别模拟 Anthropic 缓存创建/读取和 OpenAI-compatible 缓存读取/可选写入字段，统一用量事件得到正确的总输入、输出、缓存写入和缓存读取值；字段缺失、布尔值、负数或类型非法时对应指标保持未知且会话不中断。

- **AC8（F4）**：模拟同一轮多个用量快照和多轮 Agent 请求，会话累计只计入每轮最终已知快照一次，不重复累加；smoke 或调试程序能够打印已知缓存写入/读取值和未知状态。

- **AC9（F5）**：固定“工具使用”模块和相关内置工具描述中都能定位到专用工具优先、编辑前读取、精确修改和依据真实结果陈述等规则，工具描述没有无关的大段重复。

- **AC10（F6、N3、N9）**：捕获 Provider 请求可观察到补充项带 `<system-reminder>` 标签、具有系统级语义、位于稳定前缀之后且不存在于持久对话历史。用户输入同名标签后仍保持用户角色，不能改变模式或工具权限。

- **AC11（F7）**：模拟至少 17 轮同一任务，Plan Mode 完整提醒只出现在第 1、6、11、16 轮，其余轮次为精简提醒；新任务或模式切换后的下一轮重新注入完整提醒。Plan Mode 只暴露只读工具，执行层拒绝副作用工具；`/do` 恢复完整工具集并执行已确认计划。

- **AC12（F8、N2）**：同一逻辑上下文分别序列化为 Anthropic 与 OpenAI-compatible 请求后，模块内容、环境字段、reminder 语义、注入节奏和历史顺序等价；纯文本、连续工具调用、取消、流式错误及下一任务恢复的回归测试通过。

- **AC13（N3）**：Plan Mode 多轮工具调用、中途取消以及取消后再次发起任务时，Provider 请求不因角色顺序或工具配对错误返回协议错误，持久历史中没有遗留 reminder。

- **AC14（F2、N4、N5）**：在非 Git 目录、Git 不可用和环境字段读取失败的测试中，环境块安全省略不可用字段或显示安全状态，请求正常发起且界面不阻塞；输出不包含测试设置的 API Key、环境变量、remote URL 或文件内容。

- **AC15（F3、F4、F9）**：通过 tmux 使用同一真实模型重复发送具有相同稳定前缀的请求，验收记录包含 Provider 实际返回的缓存写入、读取或未知状态。达到端点最低 Token 门槛后预期后续请求出现缓存读取；若端点因尽力而为、过期或其他外部限制仍返回零或缺失，不得标记命中通过，必须记录实际结果与限制。
