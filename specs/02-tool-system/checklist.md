# MewCode 工具系统 Checklist

> 每项均以可观察行为或可重复运行的命令验证。验收时记录实际命令输出、界面观察或 tmux 截图，不以代码阅读代替验证。

## 工具定义与协议注入

- [ ] 六项固定工具均可被列出并按名称查找；重复或未知名称得到明确结果。（验证：运行 `pytest -q tests/test_tool_registry.py`，并断言工具数为 6。）
- [ ] Anthropic 首次请求包含六项名称、描述与输入规则均完整的工具定义。（验证：运行 `pytest -q tests/test_anthropic.py`，检查模拟服务捕获的请求体。）
- [ ] OpenAI 首次请求包含六项名称、描述与输入规则均完整的 function 工具定义。（验证：运行 `pytest -q tests/test_openai.py`，检查模拟服务捕获的请求体。）
- [ ] 内置提示词把模型描述为可使用工具的 Agent，并说明真实结果优先、外部路径审批与单轮限制。（验证：运行对应提示词断言，确认旧的“不能调用工具”文本不再存在。）

## 六项工具

- [ ] 读取文本文件时，结果包含内容和行号。（验证：在隔离目录读一个多行 UTF-8 文件，比较返回行号与内容。）
- [ ] 读取不存在、不可读或非文本文件时，得到结构化失败结果，应用不崩溃。（验证：运行 `pytest -q tests/test_tools_files.py`。）
- [ ] 写文件可以新建、覆盖并创建缺失父目录，落盘内容准确。（验证：在隔离目录写普通路径和嵌套路径后读取磁盘内容。）
- [ ] 写入或修改失败不会留下部分内容或损坏既有文件。（验证：构造写入失败并比较操作前后文件字节内容。）
- [ ] 改文件在原文恰好出现一次时只替换该处。（验证：对带唯一片段的文件执行替换并比较结果。）
- [ ] 改文件原文匹配零次或多次时，返回实际匹配数，且目标文件不变。（验证：分别执行两种情形并比较操作前后文件字节内容。）
- [ ] 命令结果同时包含标准输出、标准错误和退出码；非零退出作为结构化结果而非异常退出。（验证：运行成功和故意失败的命令，检查三项结果。）
- [ ] 超时命令被终止，进程组被回收，TUI 与会话仍可继续。（验证：运行 `pytest -q tests/test_tools_command.py`，随后执行一条成功命令。）
- [ ] glob 查找返回匹配文件路径且不把目录误当作文件。（验证：对含嵌套文件和目录的临时树运行 `**/*.py`。）
- [ ] 代码搜索返回文件、行号和命中文本；无结果是结构化结果。（验证：对已知关键字及不存在关键字分别搜索。）
- [ ] 大文件、长命令输出和大量搜索命中会截断，且结果和工具行明确标明截断。（验证：运行 `pytest -q tests/test_tools_files.py tests/test_tools_search.py tests/test_tools_command.py`。）

## 系统级沙箱与外部访问

- [ ] 默认权限允许当前工作目录读写与系统临时目录写入，但工具子进程没有网络访问。（验证：在工作目录内读写成功；从命令工具发起网络访问失败。）
- [ ] 所有文件工具和命令工具的子进程使用同一沙箱边界。（验证：以读文件和命令两种方式访问未授权外部文件，均被拒绝。）
- [ ] 工作目录外访问显示工具、解析后的真实路径、所需读/写/执行权限及命令摘要，并可用方向键选择授权范围。（验证：在 TUI 触发外部路径访问，检查授权 modal 的内容、默认焦点和键盘行为。）
- [ ] 拒绝外部访问后返回结构化错误，且外部文件未读取或修改。（验证：选择“拒绝”，比较外部文件内容和修改时间。）
- [ ] “仅本次允许”的读授权只允许当前调用读取，不允许写入或供后续调用复用。（验证：首次读取成功；随后写入与再次读取分别被拒绝或重新要求授权。）
- [ ] “本会话允许”的目录写授权允许同目录后续操作，但不授权父目录或相邻目录；退出重启后授权失效。（验证：同目录写入成功、相邻目录失败，重启后再次请求授权。）
- [ ] 相对路径逃逸和符号链接均不能绕过授权范围。（验证：分别传入 `..` 路径与指向外部位置的链接，观察拒绝结果。）
- [ ] 工作进程不继承 API Key、代理凭据等敏感环境变量。（验证：在测试中注入假密钥并运行 `pytest -q tests/test_tool_worker.py tests/test_sandbox_backends.py`。）
- [ ] 当前平台没有可用原生沙箱后端时，工具返回不可用错误，绝不降级为宿主无隔离执行。（验证：模拟后端缺失并运行 `pytest -q tests/test_sandbox_backends.py`。）

## 流式调用、历史回灌与单轮限制

- [ ] OpenAI 与 Anthropic 均能把分片到达的工具名称和 JSON 参数组装成完整调用。（验证：运行 `pytest -q tests/test_openai.py tests/test_anthropic.py`，检查模拟 SSE 碎片的解析结果。）
- [ ] 正文文本、thinking 增量和工具调用不混淆；thinking 内容不会出现在用户可见文本或工具结果。（验证：运行现有两协议 thinking 测试及新增工具流测试。）
- [ ] 首次模型响应的一个或多个工具调用按顺序执行；其中一个失败不会阻断同批后续调用。（验证：使用模拟 Provider 返回两个调用，其中第一个故意失败，检查第二个仍执行。）
- [ ] 工具调用与每项结构化结果均以正确协议格式加入历史，第二次请求可以读取这些结果。（验证：抓取两协议第二次请求体，检查调用 ID 与结果关联。）
- [ ] “读取指定文件并总结”触发一次工具批次后，模型第二次请求生成体现文件内容的最终文本答复。（验证：运行 TUI 集成测试，并断言 Provider 被调用两次。）
- [ ] 第二次响应再请求工具时，工具不执行、不发起第三次模型请求，并显示单轮上限结果。（验证：使用返回第二批工具调用的模拟 Provider，检查执行次数与错误提示。）

## TUI、错误恢复与兼容性

- [ ] 每次工具调用都以可区分工具行显示工具名、关键参数、执行状态和结果摘要，并保留在可滚动历史中。（验证：运行 `pytest -q tests/test_app.py tests/test_screens.py`，检查组件和滚动高度。）
- [ ] 工具参数错误、文件不存在、授权拒绝、沙箱不可用、命令失败、超时、搜索无结果与 JSON 解析失败均显示可区分错误，随后仍可发送正常消息。（验证：逐类触发后各发送一条纯文本消息，观察会话继续。）
- [ ] 工具执行、授权选择、等待第二次模型回复期间界面不冻结，输入在结束后恢复可用。（验证：Textual 集成测试中检查 busy 期间输入禁用、滚动可用、结束后输入聚焦。）
- [ ] 未涉及工具的既有 Anthropic/OpenAI 纯文本流式对话与 thinking 丢弃行为不回归。（验证：运行 `pytest -q tests/test_openai.py tests/test_anthropic.py tests/test_app.py`。）
- [ ] 工具输出、错误文本、终端界面和测试日志不出现 API Key 或其他敏感配置。（验证：以假密钥运行全套测试并检索测试输出。）

## 编译与自动化测试

- [ ] 静态语法检查通过。（验证：运行 `python -m compileall -q mewcode`，退出码为 0。）
- [ ] 全量单元与集成测试通过。（验证：运行 `pytest -q`，退出码为 0。）
- [ ] 工作区没有格式错误。（验证：运行 `git diff --check`，无输出且退出码为 0。）

## tmux 端到端场景

- [ ] 场景 1：在临时项目目录启动 MewCode，输入“读取 `notes.txt` 并用一句话总结” → 显示读文件工具行和结果摘要，随后出现准确引用文件内容的最终答复。（验证：tmux 中观察完整两段流式过程。）
- [ ] 场景 2：输入“把 `config.txt` 中唯一的 `port=3000` 改成 `port=4000`” → 显示改文件工具行，磁盘内容只改一处，最终答复说明成功。（验证：tmux 后用外部 shell 读取文件确认。）
- [ ] 场景 3：请求读取工作目录外的临时文件 → 出现路径审批；选择拒绝时文件不被读取，重新请求并选择“仅本次允许”时可读且本会话后续访问再次要求审批。（验证：用方向键操作并观察工具结果。）
- [ ] 场景 4：请求执行一个故意非零退出的命令，再发送普通对话 → 前者显示结构化工具失败，后者仍得到正常流式回复。（验证：tmux 中连续输入两条请求。）
- [ ] 场景 5：分别以 Anthropic 与 OpenAI Provider 配置执行“搜索项目中某关键字并总结” → 两种协议均显示工具行、回灌结果和最终答复，用户可见行为一致。（验证：两次 tmux 会话对照观察。）
