# OpenAI 兼容思考模式 Spec

## 背景

MewCode 已将 DeepSeek 配置更新为 `deepseek-v4-pro` 与 `deepseek-v4-flash`。这两个模型支持思考与非思考两种模式，并默认启用思考。普通文本回复中，当前 OpenAI 兼容 Provider 会识别并丢弃 `reasoning_content`，因此最终正文通常可以正常显示。

当模型在思考模式下调用工具时，DeepSeek 要求后续请求携带产生该工具调用的助手消息及其完整 `reasoning_content`。当前 MewCode 的统一流事件、会话历史与 OpenAI 请求序列化均没有保存该字段，工具执行后的下一轮请求可能因历史不完整返回 HTTP 400，阻断 Agent Loop。

DeepSeek 的 `thinking` 和 `reasoning_content` 是建立在 OpenAI Chat Completions 形态上的扩展，不是 OpenAI 官方接口的通用标准字段。OpenAI 官方 Chat Completions 使用 `reasoning_effort` 控制其推理模型，因此 MewCode 既不能把 DeepSeek 扩展无条件发送给所有 OpenAI 端点，也不应通过模型名或厂商地址写专用分支。

本规格把这项能力实现为 OpenAI-compatible Provider 的显式可选扩展：配置明确声明时发送思考开关，响应实际提供 `reasoning_content` 时按通用规则保存和回灌，同时继续禁止在用户界面展示模型思考内容。

## 目标

- 让 OpenAI-compatible provider 的 `thinking: true` 与 `thinking: false` 显式映射为扩展请求参数；未配置时不发送扩展字段。
- 在思考模式的工具调用链中保存并回传协议要求的思考内容，使多轮 Agent Loop 正常推进。
- 思考内容仅用于协议续传，不进入 TUI、用户正文、工具摘要、错误提示或日志。
- 不依赖模型名、厂商名或 `base_url` 识别能力；让任何采用相同扩展字段的 OpenAI 兼容端点直接复用。
- 保持普通文本对话、取消、流式错误恢复、Anthropic Provider 和未启用扩展的 OpenAI 兼容端点的既有行为。
- 用自动化测试与真实 DeepSeek API 工具任务验证完整链路。

## 功能需求

- **F1（显式扩展开关）**：OpenAI 协议的 `thinking` 配置必须区分真、假和未配置三种状态。配置为真时发送 `thinking.type=enabled`，显式配置为假时发送 `thinking.type=disabled`，未配置时不得发送 `thinking`。配置值必须是 YAML 布尔值，不能把字符串等其他类型静默转换为真。

- **F2（响应驱动接收）**：任何 OpenAI 兼容端点流式响应中的 `reasoning_content` 增量都必须与正文增量区分接收，不依赖模型名或地址判断。思考增量仅进入内部 Agent 处理链，不得作为正文或公开 Agent 事件发布。

- **F3（工具回合关联）**：一轮响应包含工具调用时，该轮完整思考内容必须与同一条助手工具调用消息关联保存；前置正文、思考内容和工具调用必须保持来自同一模型回合。没有工具调用的最终文本回合不保留思考内容。

- **F4（响应驱动回传）**：只要某个 OpenAI 兼容响应实际提供了 `reasoning_content` 且同轮包含工具调用，后续请求就必须为该助手消息序列化原始 `reasoning_content`，不再判断模型或厂商。连续多轮工具调用时，每个相关助手回合都要携带各自的思考内容；即使模型没有生成工具调用前置正文，对应助手消息的 `content` 也必须是空字符串而不是 `null`。

- **F5（界面隔离）**：TUI 只能收到现有的正文、工具、用量、迭代和错误等公开 Agent 事件。无论正常完成、工具失败、取消、达到迭代上限还是流式错误，思考内容都不得进入可见文本。

- **F6（生命周期完整性）**：工具执行期间取消时，已记录的助手工具调用及其思考内容必须与结构化取消结果保持配对；任务恢复后的下一次请求仍具有合法历史。未形成完整工具调用就被取消或流式失败的响应不得留下孤立思考历史。

- **F7（协议与配置隔离）**：不得通过模型名、厂商名或 `base_url` 决定思考行为。Anthropic 沿用自身协议；OpenAI 兼容配置未出现 `thinking` 时不发送扩展开关，历史中未实际收到 `reasoning_content` 时不增加回传字段。

- **F8（错误可恢复）**：DeepSeek 返回 HTTP 或网络错误时，继续沿用现有结构化错误事件与任务停止语义，不输出密钥或内部思考内容，用户随后可以发起新任务。

## 非功能需求

- **N1（隐私）**：思考内容仅存在于当前进程内存和发往同一模型服务的协议历史中，不持久化、不记录日志、不写入工具结果。
- **N2（兼容性）**：官方 OpenAI、现有兼容端点、Anthropic、纯文本流式回复和未启用扩展的请求均不得回归。
- **N3（顺序一致性）**：思考增量、正文增量、工具调用与工具结果的归属不能跨模型轮次混淆；取消和并发工具执行不得改变历史顺序。
- **N4（最小改动）**：复用现有统一事件流和会话历史，不引入 Provider 全局缓存、回调旁路或第二套 Agent Loop。
- **N5（可测试性）**：请求体、流式解析、内部隔离、历史保存、连续工具回灌、取消和协议隔离均须有确定性的自动化测试。

## 不做的事

- 不展示、折叠展示、导出或持久化思考内容。
- 不新增 `reasoning_effort`、思考预算或 high/max 档位配置。
- 不重新设计 Anthropic 的扩展思考协议；本期只保证其既有行为不变。
- 不增加任何 DeepSeek 模型名、厂商地址或旧别名判断。
- 不把 DeepSeek 扩展误称为 OpenAI 官方标准，也不在本期实现 OpenAI 官方 `reasoning_effort` 配置。
- 不改变模型选择、API Key 管理、Provider 切换或会话持久化机制。
- 不增加自动重试、历史压缩或 Token 成本统计规则。

## 验收标准

- **AC1（F1）**：对任意 OpenAI-compatible 模型捕获请求体时，`thinking: true` 得到 `{"thinking":{"type":"enabled"}}`，显式 `thinking: false` 得到 `{"thinking":{"type":"disabled"}}`，未配置时请求中不存在 `thinking`；非布尔配置在启动期报可读错误。
- **AC2（F2、F5）**：模拟同时包含思考和正文的 SSE，内部能够收集完整思考内容，但公开 Agent 事件和正文中只出现最终正文。
- **AC3（F3、F4）**：模拟“思考 → 工具调用 → 工具结果 → 最终答复”，第二次模型请求的对应助手消息包含原始 `reasoning_content`、正文和工具调用，且工具结果紧随其后；没有前置正文时 `content` 为 `""` 而不是 `null`。
- **AC4（F4、N3）**：模拟至少两轮工具调用，每轮思考内容只出现在所属助手消息中，顺序正确且任务最终正常完成。
- **AC5（F6）**：工具执行期间取消后，助手工具调用、隐藏思考内容和取消结果配对完整；再次发起任务不会产生协议历史错误。
- **AC6（F7、N2）**：同一个 OpenAI Provider 使用任意模型名和自定义地址时均遵循显式配置与响应驱动规则；未配置 `thinking`、未收到 `reasoning_content` 的官方 OpenAI 请求保持原序列化结果，Anthropic 行为不变。
- **AC7（F5、N1）**：自动化测试检查所有公开 Agent 事件、工具摘要和错误文本，均不包含测试用思考秘密字符串。
- **AC8（F8）**：模拟 DeepSeek HTTP 400 后任务以流错误结束、不崩溃，错误信息不含密钥或思考内容，下一条任务可以正常运行。
- **AC9（端到端）**：在 tmux 中分别选择 DeepSeek V4 Pro 和 Flash、开启思考模式，完成至少一次真实文件读取工具任务；工具执行后模型继续生成最终答复，期间无 HTTP 400 且界面不出现思考内容。
